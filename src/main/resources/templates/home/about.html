1. Project Abstract

Every college runs on announcements, yet most colleges still spread them across WhatsApp groups, printed notices, class representatives, and scattered emails. Something urgent — a postponed exam, a placement drive, a fee deadline — can quietly get lost between five different channels, and no one at the top ever really knows who has actually seen it.

The Smart College Announcement and Notification Management System fixes this by giving the entire college one place to publish, target, and track every announcement, from the smallest circular to a campus-wide alert.

Faculty and admins compose an announcement once, choose exactly who it is for — a single class, a department, a graduating batch, or everyone — and the system instantly delivers it as an in-app notice and email log. Students and faculty open a single, always-current dashboard with built-in search, category filters, and a simple read/acknowledge trail that finally gives admins a real picture of who has seen what.

2. High-Level System Architecture

[Client Devices] Desktop Browsers · Tablets · Android/iOS Mobile Devices (Vanilla HTML5 + Responsive CSS)
▼ HTTP/HTTPS Requests (Cookies, CSRF Token)
[Security Filter Chain] Spring Security 6 (BCrypt Password Hashing · Role Authorization: STUDENT / FACULTY / ADMIN)
▼ Authorized Session
[Controller Layer] AuthController · DashboardController · AnnouncementController · NotificationController · AdminController
▼ Business Validation & DTO Mapping
[Service Layer] AnnouncementService · NotificationService (Targeting Matcher) · AcknowledgementService · AnalyticsService
▼ Spring Data JPA / Hibernate Transactions
[Persistence Layer] MySQL 8.x Database (`smart_college_announcements_db`) & File Storage (`uploads/`)
Controller Layer: Validates incoming requests and delegates commands cleanly.
Service Layer: Encapsulates notification dispatching, targeting filters, and reach calculation.
Repository Layer: Spring Data JPA entities turning calls into optimized SQL.
Thymeleaf View: Server-rendered HTML with zero JavaScript bundle overhead.

3. Entity–Relationship (ER) Design

The data model cleanly separates identity (USER, ROLE, DEPARTMENT) from content (ANNOUNCEMENT, ATTACHMENT) and delivery tracking (ANNOUNCEMENT_TARGET, NOTIFICATION, ACKNOWLEDGEMENT).

Entity Key Attributes Relationships Description
USER id, fullName, email, password, rollNumber, role, academicYear, section Belongs to DEPARTMENT; Has many NOTIFICATIONS Students, Faculty, and Admin accounts authenticated via Spring Security.
DEPARTMENT id, code (CSE, IT, etc.), name, description, active Has many USERS; Referenced by TARGETS University academic divisions used for identity & announcement targeting.
ANNOUNCEMENT id, title, content, category, priority, status, publishedAt, isPublic Authored by USER; Has many TARGETS, ATTACHMENTS, ACKS Core circular item published with priority ribbons and expiry dates.
ANNOUNCEMENT_TARGET id, targetDepartment, targetYear, targetSection, targetRole Many-to-One ANNOUNCEMENT Rules defining exact audience (e.g. CSE Dept, 2nd Year, Section A).
NOTIFICATION id, isRead, readAt, channel (IN_APP, EMAIL), createdAt Many-to-One USER; Many-to-One ANNOUNCEMENT Automated delivery record dispatched immediately on publishing.
ACKNOWLEDGEMENT id, acknowledgedAt, remarks Unique Pair (USER, ANNOUNCEMENT) Append-only confirmation record feeding the admin reach analytics.
ATTACHMENT id, originalFileName, storedFileName, fileType, fileSize, filePath Many-to-One ANNOUNCEMENT Uploaded circular PDF documents or timetable images.

4. Comparison: Existing Process vs. Proposed System

Evaluation Aspect Manual / WhatsApp Notice Boards Proposed Smart College System
Reaching Everyone Manual forwarding; students miss group chats or circulars. Automatic, role-targeted delivery to matching accounts.
Finding an Old Notice Tedious scrolling through hundreds of chat messages. Instant keyword search & category filters in under 2 seconds.
Proof of Readership Zero visibility into who read an urgent notice. Live read rate % & acknowledgement audit trail per circular.
Device Compatibility Dependent on WhatsApp mobile app. Responsive Vanilla HTML/CSS working on any browser, phone or lab PC.
Archiving & Security Messages deleted or lost when members leave groups. Permanent, role-governed MySQL database backed by BCrypt auth.
